# 原版人物分叉推演

这里测试原版移动状态复制和局部动作搜索，不训练 RL，也不替换现有寻路。

`VanillaFrame.Capture(player, tileRectangle)` 读取人物值字段、原版装备、额外跳跃状态、周围方块和液体、相关静态字段及随机数状态。结果可以 JSON 传给独立进程。

`VanillaPrediction(snapshot).Predict(keys)` 在临时专用服务器中重建人物，每帧设置方向键并调用真实 `Player.Update`，返回逐帧位置、速度、生命、翅膀时间、跳跃和 buff 状态。最多推演 120 帧；离开已知区域、死亡或生成不支持的动态实体时提前停止。结束或异常都会恢复检查点，可以从同一状态尝试另一组输入。

输入是按位组合：左 1、右 2、跳 4、上 8、下 16。例如 `[6, 6, 2, 6]` 表示右跳两帧、松开跳跃一帧、再次右跳。重力药水用上键，冲刺用对应方向双击；这些效果走原版逻辑。

## 运行

在 TerraBlind 根目录执行：

```
dotnet build tests/Forecast/Forecast.csproj '-p:ExtraBuildModFlags=-tmlsavedirectory /tmp/terrablind-forecast-lab' -v q --nologo
python3 -u tests/Forecast/check.py
```

Python 只用标准库。脚本创建或复制临时小世界，只启用 Forecast 测试模组，使用本机游戏端口 17978 和 RPC 端口 19042。只终止自己启动的进程。正式 Mods、人物、世界和远程服务器均不修改。

输出：

- `/tmp/terrablind-forecast-lab/engine.log`：本次引擎日志。
- `/tmp/terrablind-forecast-lab/result.json`：逐帧轨迹、误差、推演耗时、引擎标识和未复制的引用字段。
- `VANILLA_FORECAST_CHECKS_COMPLETE`：全部检查及能力触发断言完成后才输出。

每个场景都执行 A 输入、B 输入、再执行 A，检查原人物没有变化、检查点完整恢复、A 的结果可重复。随后让保留的原人物对象实际执行 A，逐帧对比复制人物的结果。翅膀飞行中及多段跳状态还检查经过 JSON RPC 传输后结果相同。

覆盖平地、半砖、斜坡、顶头、嵌入方块、蜂蜜及蜂蜜块、五种额外跳跃及其组合、气球、两种翅膀、飞行中途复制、羽落及过期、重力翻转、减速/寒冷/蛛网/冰冻、忍者冲刺和摔落伤害。另有断言确保额外跳跃确实增加高度、翅膀时间确实消耗、重力确实翻转等，避免只证明两条无效输入轨迹相同。

## 验证边界

这是隔离引擎中的人物更新对照，不是正常客户端验收，也不是整个世界未来的模拟。NPC、弹幕、掉落物、液体流动、机关和世界时间不逐帧运行。只能预测固定地形中人物自身的更新。

当前主动拒绝正在使用物品、激活的坐骑/钩爪、模组物品、带导线的区域及区域内动态实体。物品只恢复原版类型、前缀和数量；未复制的复杂引用明确列在结果中。不能据此宣称所有原版状态或其他模组已经兼容。

无界面服务器缺少客户端视觉及成就系统。只在带 `-vanillaforecastport` 且保存目录位于临时目录的专用进程内，跳过生物群系计算的视觉尾部、成就通知和人物存盘，提供一个无图形设备的视图矩阵。按键在原版 `ResetControls` 之后注入，保留原版后续的冰冻等输入限制；不修改跳跃、装备、buff、碰撞或伤害算法。预测还需与正常客户端逐帧对照，才能确认这些适配没有遗漏相关客户端行为。

正式模组没有接管 `RecedingNav`，也没有在玩家后台启动训练或服务。把这个后端用于游戏中的实时搜索前，仍需要客户端对照、异步跨进程接入和过时结果处理；不能把本实验当作现有寻路已经升级完成。

## 局部选路闭环

构建后执行 `python3 -u tests/Forecast/check.py --navigation`。输出为 `/tmp/terrablind-forecast-lab/navigation.json`，全部断言通过后输出 `VANILLA_NAVIGATION_CHECKS_COMPLETE`。

生产代码 `VanillaLocalPlanner` 接收快照、人物左上角的目标坐标以及上次未执行的按键。最多尝试22个候选，每个90帧：继续上次路线、等待、行走、不同起跳时机和按住时长、松开再跳、松开方向减速；持有重力药水效果时另试一次上键翻转。没有按装备类型硬编码选路规则。

每个候选调用同一引擎推演。死亡、掉血、离开快照范围或生成不支持的动态实体时拒绝。其余候选按途中最近距离加末帧距离的四分之一评分，另对消耗的翅膀时间和额外跳跃次数计少量代价。返回整条预测及前8帧可执行按键；所有候选均不安全时返回 `no_safe_candidate`，不提供动作。

测试驱动让保留的原人物执行前8帧，然后重新拍快照、搜索。每一帧执行位置都与刚才预测对比，规划时检查原人物字段没有被修改。场景包含平地、裸装无法登上的12格高台、多段跳组合或翅膀登高台、云朵瓶越8格墙、裸装在熔岩坑边停留、翅膀越过熔岩坑，以及已在空中且无法避免摔伤时拒绝输出安全路线。检查实际用到了额外跳跃/翅膀，以及确实拒绝了预测会掉血的候选。

`SnapshotArea` 围绕人物和目标截取局部范围，向上留30格、向下留24格、左右各约8格，并受快照160格边长限制。范围外的候选会被拒绝；这不是对未知区域安全性的推断。

耗时记录分为拍快照、恢复、人物更新、轨迹记录和最终恢复。搜索使用精简轨迹，保留详细轨迹的原接口仍用于29项状态复制回归。这里没有动态调整帧时序：测试世界在规划期间不推进，不能据此证明真实客户端能达到60Hz，也不能保证90帧之后的安全性。动作库与局部目标不足以处理所有复杂地形，停留或限帧失败仍需上层换目标或恢复策略。

## 图形客户端对照与异步测试

构建后运行：

```
python3 -u tests/Forecast/client.py
python3 -u tests/Forecast/client.py --async
```

会弹出一个独立 tModLoader 窗口。它使用 `/tmp/terrablind-forecast-client` 下的本地人物、世界副本、配置和仅启用 Forecast 的模组目录；不会枚举选择云端人物或世界。图形客户端启动时明确关闭新人物的云存档，并校验人物路径属于临时保存根目录。原版人物创建后再按正常存档加载流程读取，避免直接使用未初始化的 `new Player()` 进入世界。

测试场地会被清空后放置障碍。仅在带 `-forecastclient` 的临时客户端中，关闭单人模式失焦暂停，使测试能在后台推进。按键通过 `ResetControls` 和正常键盘读取 `TriggersSet.CopyInto` 后注入，保持原版后续的输入限制、人物更新、世界更新与图形系统运行；不调用 `VanillaPrediction.Advance` 来代替客户端帧。

第一个命令覆盖平地、半砖、顶头、蜂蜜、云朵瓶、翅膀、羽落、重力翻转和冰冻。后台任务将当前客户端快照送给独立工作进程，客户端同时正常执行72帧按键，再逐帧比较预测及实际状态。结果在 `client-result.json`；通过标记为 `GRAPHICAL_CLIENT_CHECKS_COMPLETE`。它覆盖这些受控场景，不能推广为多人或全部原版状态验收。

异步生产协调器 `VanillaAsyncMovement` 不阻塞游戏等待规划：

1. 在客户端帧末拍快照，取出交接前已经排定的按键；没有已排定输入时使用松键。提前量从30帧开始，发生迟到时按实际观察到的响应帧数加6上调，最多90帧。
2. 工作进程先推演交接前这些输入，到预计交接状态，再从交接状态搜索90帧路线。
3. 客户端继续执行之前排定的输入，不等待网络结果。提前返回的结果也必须等到交接帧。
4. 到交接帧，检查指令版本、装备和快照区域的方块/液体，以及实际位置、速度、生命、翅膀、多段跳和buff状态是否匹配预测。区域内出现NPC、弹幕、掉落物或导线，人物启用坐骑/钩爪或使用物品时也拒绝。迟到、版本变化、上下文变化和状态不一致都拒绝，清空旧输入。
5. 匹配后从下一帧安装新按键，继续异步规划。调用方必须在目标或指令变化时递增版本；这个模块尚未挂入正式寻路或任务执行器。

`--async` 检查正常平地移动、带翅膀登12格高台，以及注入1秒延迟、指令版本变化、方块变化、击退后的拒绝行为。逐帧记录 `Main.GameUpdateCount` 并断言连续增长，检查世界没有为规划暂停。结果在 `async-result.json`，通过标记为 `ASYNC_CLIENT_CHECKS_COMPLETE`。正常场景也可能因为请求迟到或环境buff变化拒绝结果，成功到达不代表请求全部有效，更不代表稳定的实时性能。

默认无界面回归另有一个使用合成传输结果的协调器契约检查：先安装路线，再制造速度不一致，确认拒绝时连同旧输入一起清除；随后在区域内创建弹幕，确认旧计划被拒绝。这个检查只证明协调器的失效及队列清理逻辑，不作为移动正确性的证据。
