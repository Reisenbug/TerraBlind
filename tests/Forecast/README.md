# 原版人物分叉推演

这里测试的是状态复制是否足够保留原版移动行为，不训练 RL，也不替换现有寻路。

`VanillaFrame.Capture(player, tileRectangle)` 读取人物值字段、原版装备、额外跳跃状态、周围方块和液体、相关静态字段及随机数状态。结果可以 JSON 传给独立进程。

`VanillaPrediction(snapshot).Predict(keys)` 在临时专用服务器中重建人物，每帧设置方向键并调用真实 `Player.Update`，返回逐帧位置、速度、生命、翅膀时间、跳跃和 buff 状态。最多推演 120 帧；离开已知区域、死亡或生成不支持的动态实体时提前停止。结束或异常都会恢复检查点，可以从同一状态尝试另一组输入。

输入是按位组合：左 1、右 2、跳 4、上 8、下 16。例如 `[6, 6, 2, 6]` 表示右跳两帧、松开跳跃一帧、再次右跳。重力药水用上键，冲刺用对应方向双击；这些效果走原版逻辑。

## 运行

在 TerraBlind 根目录执行：

```
dotnet build tests/Forecast/Forecast.csproj '-p:ExtraBuildModFlags=-tmlsavedirectory /tmp/terrablind-forecast-lab' -v q --nologo
python3 -u tests/Forecast/check.py
```

Python 只用标准库。脚本创建或复制临时小世界，只启用 Forecast 测试模组，使用本机游戏端口 17978 和 RPC 端口 19042。只终止自己启动的进程。正式 Mods、人物、世界和远程服务器均不修改。

输出：

- `/tmp/terrablind-forecast-lab/engine.log`：本次引擎日志。
- `/tmp/terrablind-forecast-lab/result.json`：逐帧轨迹、误差、推演耗时、引擎标识和未复制的引用字段。
- `VANILLA_FORECAST_CHECKS_COMPLETE`：全部检查及能力触发断言完成后才输出。

每个场景都执行 A 输入、B 输入、再执行 A，检查原人物没有变化、检查点完整恢复、A 的结果可重复。随后让保留的原人物对象实际执行 A，逐帧对比复制人物的结果。翅膀飞行中及多段跳状态还检查经过 JSON RPC 传输后结果相同。

覆盖平地、半砖、斜坡、顶头、嵌入方块、蜂蜜及蜂蜜块、五种额外跳跃及其组合、气球、两种翅膀、飞行中途复制、羽落及过期、重力翻转、减速/寒冷/蛛网/冰冻、忍者冲刺和摔落伤害。另有断言确保额外跳跃确实增加高度、翅膀时间确实消耗、重力确实翻转等，避免只证明两条无效输入轨迹相同。

## 验证边界

这是隔离引擎中的人物更新对照，不是正常客户端验收，也不是整个世界未来的模拟。NPC、弹幕、掉落物、液体流动、机关和世界时间不逐帧运行。只能预测固定地形中人物自身的更新。

当前主动拒绝正在使用物品、激活的坐骑/钩爪、模组物品、带导线的区域及区域内动态实体。物品只恢复原版类型、前缀和数量；未复制的复杂引用明确列在结果中。不能据此宣称所有原版状态或其他模组已经兼容。

无界面服务器缺少客户端视觉及成就系统。只在带 `-vanillaforecastport` 且保存目录位于临时目录的专用进程内，跳过生物群系计算的视觉尾部、成就通知和人物存盘，提供一个无图形设备的视图矩阵。按键在原版 `ResetControls` 之后注入，保留原版后续的冰冻等输入限制；不修改跳跃、装备、buff、碰撞或伤害算法。预测还需与正常客户端逐帧对照，才能确认这些适配没有遗漏相关客户端行为。

正式模组目前只包含可调用的快照及推演基础代码，没有接管 `RecedingNav`，也没有在玩家后台启动训练或服务。把这个后端用于实时搜索前，需要补客户端对照、移动动作搜索、预算和跨进程接入；不能把本实验当作寻路已经升级完成。
