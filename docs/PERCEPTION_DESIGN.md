# 像人一样玩的 bot —— 感知/执行架构设计

> 2026-07-08 与用户的架构讨论产出。目标不是玩具，是**像人一样玩**的 bot。
> 类比:眼(感知) → 手(反射级执行,代码比手快) → 脑(LLM,慢但会想)。
> 分三步谈:眼 → 手 → 脑。本文档随讨论逐节补全。

---

## 眼

**眼的第一要务是完备,不是过滤。** 先保证「不瞎」——mod 暴露的信息是能力的地板;
mod 没暴露的,不管后面策略多聪明,手和脑都永远瞎在这一点上。过滤是在完备之上做减法,
没有完备,减法可能减掉了本就缺的关键项,脑再聪明也补不回。所以顺序:**先完备,再过滤。**

### 完备性的边界

暴露范围 = **人类玩家玩这个游戏时能感知到的全部**,以此为基准线:

- **该暴露(人能感知的)**:周围地形、实体及可见状态、自身血蓝buff装备手持、
  水火岩浆、日夜天气、屏上飘的伤害数字、事件提示…… 凡是玩家盯屏幕能拿到的输入。
- **额外放宽——有利于当前行为的辅助信息可以暴露**,即使人得靠地图/翻界面才拿到。
  例:**全局地图**(丛林/地牢在哪、最近的铁矿)。理由:这项目已经够难,不给自己额外加难度;
  全局查询让脑能规划,不必让 bot 去「探索」补人类记忆里本就有的常识。
- **不该暴露(人感知不到的游戏内部态)**:NPC 的 AI 计时器、世界种子、刷怪权重表、
  tile 内部 wall 原始数据…… 暴露这些是开天眼,不是像人;且让脑要处理人类玩家从不用的信息。

> 一句话:**完备 = 人类玩家感知的全集 + 有利于行为的辅助查询(如全局地图),
> 不是游戏内部状态全集。**

### 眼分两路输出(同一现实,两种格式,别用一个 get_state 硬扛两头)

现在的 mod 只有一种输出(get_state 全量 JSON),被迫同时喂手和脑,两头都不对:
喂手不够快不够全,喂脑太多太原始(几 KB 塞进 history 撑爆 token)。眼该分两路:

- **A 路 → 手/技能(帧级、全量、原始、直读内存)**
  手要躲、瞄、踩实地,需要此刻周围每格的真相,快(帧级)、全、原始(坐标/tile/实体,不解释)。
  这一路**直接读 `Main.tile` / `Main.npc`** 内存,零成本、不序列化、不过网络。**已存在**——
  RecedingNav 就是这么读地形的。手不用「做」眼,自己就能看。

- **B 路 → 脑/LLM(事件级、极简、已描述、主动推)**
  脑不需要 everything;被灌 everything 就是 token 老毛病。脑要的是「发生了什么值得你醒来」——
  一句人话,不是数据。本质是 **差分 + 显著性过滤 + 描述**:
  - **差分**:这帧 vs 上帧,什么变了?没变化就沉默。
  - **显著性**:变化里哪些够格唤醒脑(史莱姆入视野=够格;草在飘=不够格)。阈值/规则在 mod 里判,
    快且便宜,不该让 LLM 读全量自己筛。
  - **描述**:够格的翻成一句给脑的话。「HP 100→64,被丛林蝙蝠咬」,不是 `{"hp":64,...}`。
  常驻沉默,只在世界发生「脑该知道的事」时推一句(走已有的 WebSocket 通道)。

### 三个尺度,三种触发(everything 分层暴露,不一次全给脑)

| 范围 | 触发 | 给谁 |
|---|---|---|
| 周围(技能作业半径,如 ±30 格) | 帧级常驻直读 | 手(A 路,直读内存) |
| 视野/警戒圈 | 差分显著性,威胁/机会才推 | 脑(B 路,被推醒) |
| 全图(丛林在哪、最近铁矿) | 脑主动查才扫 | 脑(按需,已有 find_biome/find_tiles) |

手常驻直读、脑被推醒、脑按需查。同一双眼,看的范围和给谁,由「谁要用、多急」决定。

### 待办(眼)

1. 盘一份「人类玩家感知清单」(自身/周围/实体/全局/屏幕反馈…),逐项对照现 mod 暴露了没,缺的补上 —— 这是完备性的落地。
2. B 路差分器 + 显著性过滤 + 描述器(帧级常驻,主动推)。
3. A 路确认技能都走直读内存,不走 get_state 序列化。

## 手

**定位:手+脑主要干寻路之外的事**——interact、use_item、craft、loot、攻击等。
寻路是另一套(已有 RecedingNav);手管的是「对世界施加动作」这一类。

**代码比手快,但难和眼脑连。** mod 帧级操作角色(60fps),比人类反应(~200ms)快一个量级——
躲弹幕、精确瞄准、连续挖矿,代码天生碾压人手。手的能力不是问题,**难点在「连」**:
- 手←眼:用眼 A 路(帧级直读内存)做实时闭环,**已通**(RecedingNav 直读地形)。
- 手←脑:真难点。脑(LLM,秒级)和手(帧级)差 3 个数量级,**手不能等脑逐帧发指令**。
  手拿到一个**意图**后自己跑完,只在搞不定时回头找脑。

### 手 = 带完成侦测的帧级动作闭环(不是发射即返回)

现在 interact/use_item 是**发起即返回**(点一下、挥一下就完事)——那只是抽动,不是手。
真正的手做完一个动作要知道「做成了没」,做不成要自己重试或上交。砍树 = 挥斧 + 盯着树倒 +
没倒就继续/换法。**「盯着结果、闭环到成」才是手。** 每件事都是带完成条件的小闭环:

| 手的事 | 现在(发射即返回) | 该是(闭环到成) |
|---|---|---|
| use_item 砍树/挖矿 | 挥60帧就回 | 挥到 tile 消失 or 超时(已做) |
| interact 开箱 | 点一下就回 | 点到箱子真开了(UI 状态变了) |
| craft 合成 | 发一次 | 合到背包真多成品 or 缺料 |
| loot 捡东西 | 抓一把 | 捡到附近掉落清空 |
| 攻击 | 挥武器 | 打到目标死 or 脱离 |

**手和眼绑死**:手做动作,眼盯结果,构成闭环。呼应「每个行为都需要对应的侦测方式」。

### 手要能并行:主动作 + 保命反射

人挥斧时同时踩实地、余光警戒。手不该纯串行(一次一件、做完才下一件)。至少:
**主动作(挖/砍/交互)跑着时,保命反射(别掉岩浆、被打躲一下)能插进来。** 这是
「多时间尺度并行回路」在手层的落地——否则一挖矿就对威胁全瞎。

### 反射逻辑层:慢脑够不着的快循环,靠纯逻辑补位

人的「眼脑手超快循环」(砍一下→看倒没→再砍),bot 的脑(LLM 秒级)插不进这个频率,
且没有绝妙办法把 LLM 降到帧级。**所以这个循环必须由不带 LLM 的纯逻辑在帧级跑**:
`if tree is down then stop`、`if block destroyed then stop`。逻辑吃眼的信息,驱动手。
**这是我们缺的那层。**

**别写 N 个 if,否则退回打补丁。** `if tree down`/`if chest opened`/`if craft done` 各写各的,
写到死还写不全。提炼共同形状——它们是同一个东西:

> **每个动作 = 「每帧做的事」+「终止条件 predicate(读眼)」+「超时」。**
> 帧级循环永远干同一件事:`每帧做动作; if 终止(眼) then done; if 超时 then 上交脑`。

砍树(挥斧, 目标tile消失)、挖矿(挥镐, **同一个 predicate**)、开箱(右键, 箱UI开)、
合成(点配方, 背包多成品)……**共同骨架只有一个,变的只是 predicate 和每帧动作。**
所以不是 N 个 if,是**一个帧级执行器 + 一张「动作→(每帧动作, 终止predicate, 超时)」表**。
加新动作 = 填一行表,不是加一段逻辑。这样才不退回打补丁。

**终止判定要三分,不是二分(只有 stop 会漏「白做」):**
- **成了**(tile 没了)→ 自己消化,继续下一个
- **无进展**(挥了但目标毫无变化——斧太弱、tile 太硬)→ 停,上交脑「砍不动」
- **超时兜底**(防 predicate 写漏)→ 停,上交脑

人砍两下没反应就知道「这斧不行」,不会傻挥到超时。我们刚做的 removed/timeout 只有
「成/超时」,**漏了「无进展」这个最像人的判断**,待补。

### 手总结

> 手 = 一组带完成侦测的帧级动作闭环(寻路之外:interact/use_item/craft/loot/攻击/…),
> 每个自己闭环到成或如实上交;主动作与保命反射并行,非纯串行。
> 底层是**一个帧级执行器 + 一张动作表(每帧动作/终止predicate/超时)**,predicate 读眼,
> 三分判定(成/无进展/超时)。纯逻辑不含 LLM,跑帧级,补人类『眼脑手超快循环』里慢脑够不着的部分。

### 待办(手)

1. 提炼帧级执行器 + 动作表骨架(替掉现在每动作单独一段的写法)。
2. 给每个动作补终止 predicate(读眼),尤其补齐「无进展」判定。
3. 主动作 + 保命反射的并行机制。

## 脑

**脑 = 只做「非做不可才用 LLM」的事。** 眼和手把能自动化的都吃掉了,剩给脑的才是脑该干的:
眼能差分过滤的不给脑,手能帧级闭环的不给脑。脑住在秒级慢层,永远不碰帧和格子。
LLM 反应太慢,大部分时间**该睡着**。

### 脑的四职责

1. **理解指令**:`/tb 去丛林发育` → 机器意图。自然语言,手写解析覆盖不完。
2. **规划/拆解**:开放目标 → 下发给手的一串意图。且是**活的**——不是冻结的子任务列表,
   每次被唤醒重看现实重算(意图连续变形)。人不「执行列表」,人「维持一个意图,让它在现实里流动」。
3. **对话**:澄清、汇报、协商。像队友的全部所在。
4. **异常决策**:手上交「砍不动/走不到/箱子空」时,脑决定改道(换镐?绕路?问玩家?)。
   正是手三分判定里「无进展/超时」上交的接收端。

### 意图 = (目标, 完成条件)——单动作与任务是同一套闭环的不同粒度

脑自选粒度:一次性的下发单动作(开那个箱),重复型的下发带完成条件的任务(砍够20木)。
**但两层不是两套独立机制**(那要维护两份、还会打架),是**同一个东西的两种粒度**:

> **单动作 = 完成条件最简单的任务。** 「开那个箱」= 终止条件为「箱子开了」的闭环,恰好一步满足;
> 「砍够20木」= 终止条件为「木头≥20」的闭环,要很多步。**同一个骨架**(手那节的:每帧动作 +
> 终止predicate + 超时),只是终止条件的「大小」不同。

```
脑下发 = (目标, 完成条件)
  开箱:   完成条件 = "这个箱子开了"     → 手一步就 done
  攒木:   完成条件 = "木头 ≥ 20"        → 手循环到 done
  砍这棵: 完成条件 = "坐标X的树倒了"    → 手砍一棵就 done
```

**脑选粒度 = 脑选下发多大的完成条件,不是选调用哪套 API。** 手只有一套带完成条件的闭环执行器,
脑通过给不同大小的完成条件来选粒度。一套机制,粒度连续,不打补丁、不维护两份。

### 唯一要接死的缝:意图下发 ↔ 预期外上交,脑睡到被预测失败唤醒

这道缝是眼/手两节反复点到的,接不好就退回现在「每挥一斧惊醒 LLM 一次」:

- **下行(脑→手)**:脑下发 `(目标, 完成条件)`,然后**回去睡**。不逐帧发指令,不阻塞等结果。
- **手自主**:手拿完成条件自己闭环。**符合预期的完成自己消化**(砍倒一棵→继续下一棵,不惊动脑)。
- **上行(手→脑)**:只有**预期外**才 PushEvent 唤醒脑——不是动作完成就推,是**偏离预测**才推:
  - 完成条件达成(整个任务 done)→ 推(汇报)
  - 无进展/超时(砍不动、走不到、箱子空)→ 推(求决策)
  - 威胁/意外(来怪了、掉血)→ 推(打断)
  - 正常推进(砍倒一棵还没够20)→ **不推**,脑继续睡
- **脑被唤醒后**:看现实 + 目标 + 事件,**重算此刻该下发什么意图**(不查静态列表第几项)。
  意图收束是涌现的——木头够了脑自己就不再下发砍木意图,不管原计划几步。

> **接缝一句话:脑下发(目标,完成条件)后睡;手自主闭环、消化符合预期的完成;
> 只有『预测失败』(完成/无进展/威胁)才唤醒脑;脑醒来看现实重算意图,而非执行冻结列表。**
> 这一条直接砍掉 90% 的 LLM 调用,也是「像人」的核心——意识大部分时间闲着,只被意外唤醒。

### 甲方案已落地 + 致命短板:脑不懂 Terraria,规划时凭脑内错知识乱编

甲方案(plan-once,=LLM-Planner)已实现:脑一次规划扁平动作序列,手自主执行,失败才重规划。
砍树 8次LLM→1次。**但实测暴露致命问题:脑根本不懂 Terraria,规划时全凭 LLM 脑内的错知识,还编得一本正经。**
实例(去丛林):"和谐杖要魔力"(错,不要)、"世界平台""探针"(幻觉出的不存在概念)、
"丛林在左下角"(没查就断言,还在括号里自认"需先定位")。这不是执行 bug,是**知识 bug**,
且它**不知道自己不知道**。呼应最初铁律:「LLM自带的知识就是屎,必须外界查询手段」。

**根因:甲方案为省 RPM 把规划压成一次调用,代价是规划器没有任何查证环节,更没有让幻觉被纠正的机会。**

### 解药:Voyager 的真实反馈闭环(GPT-4 同样会编"acacia axe",靠撞墙+反馈磨掉幻觉)

查证 Voyager(arXiv 2305.16291,voyager.minedojo.org):它不追求 LLM 一次规划对,**接受 LLM 一定会编,
用真实环境反馈的闭环把幻觉磨掉**。四机制:

1. **环境反馈**:LLM 生成→执行→游戏返回真实状态("还差2木板")→LLM 据此改。
   治"和谐杖要魔力":真用一次,游戏反馈不消耗魔力,幻觉当场破。
2. **执行错误**:代码报错("没有 acacia axe 这物品")→喂回 LLM→它换真实的。
   治"探针/世界平台":不存在的东西一执行就报错,错误逼它换真实的。**关键:错误必须喂回让它学,
   不能只是 unknown_op 静默失败。**
3. **自我验证**:另一个 LLM 当评论家,给「状态+任务」判断"这计划真完成了吗?没有的话怎么改"。
   治"丛林在左下角":批判者对照真实状态,指出"你没查就断言"。
4. **技能库**:验证通过的代码存起来,相似任务检索复用,错的不入库。越玩可靠技能越多,越不靠现编。
   长期解药:砍树跑通就存成技能,以后直接调。

**对照甲方案的缺口:**
- 甲的「失败重规划」≈ Voyager ①②,但做得浅:(a)规划器**起手没真实数据**(道具属性/生物群系位置),
  第一版计划就烂;(b)幻觉 op 只报 unknown_op,**没喂回让它学**;(c)**完全没有自我验证**。
- 我们**已有反馈通道**(眼:动作带回 got/lost/outcome、probe/measure),只是**没接回规划器形成闭环**。

**顿悟:Voyager 的 ①② 靠的正是执行时真实游戏反馈——这恰是我们眼已在做的。有反馈,缺闭环。**

### 待办(脑) — 按此升级甲方案

1. **规划前喂真实数据(治起手就烂)**:规划器 prompt 里带上——当前道具的真实属性(射程/是否消耗/用途,
   来自 item_info,不让脑编)、可用 op 的封闭清单(编不出"探针")。远距离目标(去丛林)强制走 find_biome 不靠脑猜方位。
2. **执行错误喂回重规划(治幻觉不被纠正)**:unknown_op / 用了不存在的物品 / 机制错误 →
   把错误原文喂回规划器让它改,而非静默失败卡死。(Voyager ②)
3. **自我验证关(治没查就断言)**:规划器吐完计划,过一道「这计划靠谱吗/有没有没查证的断言」的自检
   (可同一次调用里要求它先自查再输出,省 RPM)。(Voyager ③)
4. **不确定机制强制 wiki 查**:配方/掉落/召唤条件/道具机制,规划器不确定就 wiki_search+wiki_page,禁止编。
5. (远期)**技能库**:验证通过的 plan 存成可复用技能,相似任务检索,错的不入库。= Voyager 路线,
   对应手层暂缓的「动作表」。[[project_planner_architecture]]

原有待办(仍有效):事件驱动慢循环、活意图重算、(目标,完成条件)下发、事件显著性。
