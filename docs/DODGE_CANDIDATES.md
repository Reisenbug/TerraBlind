# 第 2 步：候选走法 + 每个候选一道是非题

## 为什么换
- 现在一次问三道选择题（水平 / 竖直 / 技能）加 flee_from，各题互相看不见，会出现 Hold+Dash、Near+Rise 这种组合。
- 后果写在长文字里，Jev 要自己比较 5 个部件 × 10 个选项的距离和帧数。它做不好这种算术。
- TypeSafe 文档：候选由代码生成时，每个候选问一道 Noul（是非题）；控制流留在代码里。

## 分工
- 代码：列出候选、推演每个候选接下来一小段时间会发生什么（纯计算，不打分、不筛选）。
- Jev：对每个候选判断"按背板和现在的局面，这一步可取吗"。
- 代码：执行 Jev 给出概率最高的那个。

## 候选有哪些（待定）
方案 A，9 个：八个方向 + 原地
- 左、右：只按左或右，竖直 Hover
- 上、下：水平不动，竖直 Rise / Plunge
- 左上、右上、左下、右下：左右键 + Rise / Plunge
- 原地：什么都不按（Hover）

方案 B，在 A 的基础上，每个方向再加一个"快"的版本：
- 这个方向射程内有能勾的方块：甩钩爪过去
- 左、右：冲刺
- 最多 9 + 8 + 2 = 19 个

> 批注：最大的问题是不清楚B的效果。如果B效果好，果断选B。

## 怎么推演（待定）
- 我的位置：按游戏里的真实字段估算每个动作的速度（跑：maxRunSpeed / accRunSpeed；下落：gravity / maxFallSpeed；飞：翅膀的上升速度）。拿不准的，先在游戏里实测一次再用，不猜。
- 钩爪：拉到落点为止。冲刺：用之前实测的 vx ±14.5。
- 部件和弹幕：按当前速度直线外推。
- 碰到实心块就停（天花板、墙、地面）。

> 批注：这个是个bug坑！

## 每个候选报给 Jev 什么
- 推演期间离每个部件最近几格，会不会碰上（碰上是第几帧）
- 会不会被弹幕打到
- 结束时的位置：上下左右各还剩几格空间
- 结束时离 nearest_part 多远（打不打得到）

state 只留：血量、打不打得到（输出百分比等）、背板。部件和弹幕的原始列表不再放进 state，信息都已经算进每个候选里了。
