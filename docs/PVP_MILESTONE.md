# 弓箭 PvP 原型

`duel_player` 是连续对战工具，`fight_player` 保留原地攻击行为。没有 PvPAdventure 的类型、反射、网络包或专用规则依赖。

## 控制循环

Agent 选择目标、固定快捷栏弓、持续时间和 strategy。代码每帧瞄准、检查箭路遮挡、执行移动；每 24 个游戏帧至多发起一个 Jev 请求，只允许一个在途请求。Jev 从当前可用的保持、接近、拉开、跳跃接近/撤退和左右换侧中选择。

Jev 返回超过 1.5 秒，或请求后人物移动超过 160 像素、目标移动超过 240 像素，结果丢弃。已接受的意图最多保持 60 帧，执行时重新检查障碍；失去新决策后停止移动。服务失败停止对战，并向 Agent 返回失败原因。

首发用武器 shootSpeed 作为粗略初值；之后从本次战斗新发射的自有 arrow 弹幕观察速度、下坠加速度和下坠延迟。每帧求解瞄准，按小段检查地形遮挡。目标速度只向前外推最多 20 帧，不预知人的未来操作。

## 范围和限制

- 固定一把弓和一种普通箭，地面与小障碍跳跃。没有自动换武器、额外跳/翅膀规划、挖掘、搭建和全局绕路。
- 弹道是近似模型，不支持任意追踪、反弹、分裂或鼠标控制箭；箭路碰撞检查也不等于完整复现所有弹幕碰撞。
- 没有无伤搜索器。附近弹幕作为 Jev 的观察，不能保证及时躲避。
- HP 差值是实际前后血量，不能归因成 AI 的伤害。死亡、断连、同队、超距、缺箭、武器变化和许可撤销会停止。

## 验证

`dotnet run --project tests/Agent/AgentTests.csproj` 链接生产逻辑。PvP 检查覆盖弹道求解、遮挡、Jev 请求、旧决策、移动与开火、敌方 friendly 弹幕识别和停止清理。碰撞与人物采用替身，不证明真实引擎物理或联机命中。

`dotnet run --project tests/Agent/AgentTests.csproj -- --pvp-smoke` 从本机配置读取 TypeSafe Key，在三个虚构场景调用真实生产请求函数，不操作游戏。结束标记 `PVP_SMOKE_COMPLETE checks=3 mock_world=true`。

客户端验收：AI 装普通弓和木箭，双方开 PvP、不同队，在带少量平台和掩体的地方，要求它用弓走位对战 30 秒。人依次换位、靠近、躲到掩体后，观察追击/拉开、停止射墙和跳跃换位。用 `[pvp] scene`、`choice`、`projectile`、`stop` 日志判断，不能只凭工具完成就宣称能与人打得有来有回。
